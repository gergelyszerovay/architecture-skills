# architecture-skills

> Skills and checkers that let an agent build TypeScript packages to one architecture, document them and plan their changes, in any repository.

## 1. Problem

An agent that writes a package in a fresh session has no memory of how the last one was built:
where code goes, which block may depend on which, what a document or a spec must contain, how a
plan is written and closed. Without written rules each package drifts, and a reviewer cannot tell a
deliberate exception from an accident.

The skills write those rules down once: an architecture per kind of package (Angular, Node,
three.js) and per product (its group documents and end-to-end journeys), a profile that holds each
architecture's checkable rules in a form the linters and the architecture gate read, and the shared
skills for constitutions, layered documentation, citations, changelogs and plans. The package ships
them with the scripts that check them, so a lab installs them with `install-skills` (the package `@gergelyszerovay/install-skills`, beside them in the product) and runs the
checkers by name.

## 2. Audiences

| Audience         | Need                                                                                               | Excluded need                                     |
| ---------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| Agent            | Find, from a package's binding, the rules it must follow and the skill that explains them.         | Choosing an architecture itself.                  |
| Product builder  | Start a package from a template that already passes its checks, and keep it passing.               | Writing lint rules or checkers of their own.      |
| Reviewer         | Tell from a finding which rule it breaks and which decision stands behind the rule.                | Judging style the rules leave open.               |
| Skill maintainer | Change a rule in one place, with the profile, the checkers and the templates kept in step with it. | Supporting another framework without a new skill. |

## 3. Outcomes

| Outcome                         | Measure                                                                  | Target                         |
| ------------------------------- | ------------------------------------------------------------------------ | ------------------------------ |
| A rule is checked, not recalled | Checkable rules of a profile that no linter or gate enforces             | Each is named as `planned`     |
| Templates start green           | Package templates that fail their own checks after `new-package`         | None (`test:templates` passes) |
| A change reaches every lab      | Labs that run a skill older than their pinned package after `lab update` | None                           |
