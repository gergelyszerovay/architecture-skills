# orders

> Places customers' orders at the current catalog prices and streams each order's status changes to its owner.

## 1. Boundaries

| Concern                          | Owner                                              |
| -------------------------------- | -------------------------------------------------- |
| Pricing products                 | catalog                                            |
| Looking prices up in the catalog | composition                                        |
| Authenticating the customer      | platform: the identity arrives in the tRPC context |

## 2. Owned Records

| Record       | Kind       | Writer                                                | Notes                                                   |
| ------------ | ---------- | ----------------------------------------------------- | ------------------------------------------------------- |
| Orders       | collection | `node-block-reference:orders#makeInMemoryOrderStore`  | Held in process memory; lost on restart.                |
| Order events | collection | `node-block-reference:orders#makeInMemoryOrderEvents` | Append-only log, numbered per process; lost on restart. |

## 3. Decisions

| ID  | Decision                                                                          | Checked by | Why                                                           |
| --- | --------------------------------------------------------------------------------- | ---------- | ------------------------------------------------------------- |
| D1  | A missing order and another customer's order are indistinguishable to the caller. | test       | Customers can't probe which order IDs exist.                  |
| D2  | An order keeps the price it was placed at; later catalog prices never change it.  | test       | The charged amount is a fact about the sale, not a live view. |
